# Typhon state review — 2026-07-25

A full review of the `v1.0.0-alpha.6` tree against the shipped compiler:
what actually works, where the docs and the bundled skill disagree with the
binary, and what the example corpus really guarantees.

Everything below was verified by running `tyc` — no claim here is taken from a
document. Reproductions are given so each finding can be re-checked.

---

## 3. Compiler findings

### C1 — a forgotten `await` inside an `async def` is completely silent (soundness)

**The most serious finding.** `tyc::missing_await` fires only when the caller is
*synchronous*. A forgotten `await` inside another `async def` — by far the
likelier mistake, since that is where await-heavy code lives — produces no
diagnostic at all. No `tyc::type_mismatch` fires either: the checker types the
call by its return type regardless of whether it was awaited, so a coroutine
object flows into a concretely-typed slot unchallenged.

```python
async def fetch_a() -> dict[str, int]:
    await asyncio.sleep(0)
    return {"a": 1}

async def run() -> int:
    let b: int = await fetch_b()          # some other await, so
    let d: dict[str, int] = fetch_a()     # `async_without_await` stays quiet too
    return len(d) + b
```

`tyc check` reports **nothing**. The emitted Python dies with
`TypeError: object of type 'coroutine' has no len()` plus
`RuntimeWarning: coroutine 'fetch_a' was never awaited`.

`tyc::async_without_await` sometimes covers for this by accident — if the
caller has *no* awaits it warns about that instead — which is probably why the
gap survived.

This is squarely in the category `CLAUDE.md` permits narrowing for: the
programs it would newly reject already crash at runtime. Any fix must keep the
deliberate-deferral pattern legal:

```python
let task = fetch_a()      # bind now …
let data = await task     # … await later
```

so the narrow rule is "an un-awaited async call whose result flows into a slot
annotated with the coroutine's *return* type", not "any un-awaited async call".

Reproduction: `examples/errors/12-known-gaps/missing_await_in_async_caller.ty`.

### C2 — `tyc::implicit_any` does not cover function signatures

It fires on annotated-assignment positions only — locals, module bindings, and
class fields. Function **parameter** and **return** annotations are not checked:

```python
let xs: list = [1, 2, 3]        # ✅ error
def keys(d: dict) -> list:      # ❌ accepted silently
    return list(d.keys())
```

The signature position is the higher-leverage one — it widens every call site
*and* the whole body. Both `docs/diagnostics/implicit_any.md` and the skill
used a function signature as their worked example, i.e. documented exactly the
case that does not fire (fixed; see D3).

Closing this would reject programs that run correctly, so it is a deliberate
narrowing decision rather than a bug fix. **Corpus impact measured: zero** — no
file in `examples/` or `stress/` has a bare collection in a signature, so it
could land without touching the corpus.

Reproduction: `examples/errors/12-known-gaps/bare_collection_in_signature.ty`.

### C3 — `tyc::missing_initialiser` is dead code

The variant and constructor exist in `tyc-diagnostics` and the code is listed
by `tyc explain --list`, but **nothing in the compiler calls
`TycError::missing_initialiser`** — verified by searching every call site in
`tyc/crates/`. It can never fire.

Its doc page still described pre-v0.7.0 behaviour ("the Rust-style
declare-then-assign shape is not supported"), which v0.7.0's
definite-assignment analysis replaced — the page's own example now compiles
cleanly. A declare-only `let` that is never assigned *and* never read is
accepted silently; reading one on an unassigned path is caught by
`tyc::use_of_uninitialised`, and a second assignment by
`tyc::immutable_assign`.

Decision needed: wire it up as a dead-binding lint, or retire the code. Docs
now describe the current reality either way.

Reproduction: `examples/errors/12-known-gaps/unassigned_declare_only_let.ty`.

### C4 — `tyc::contains_secret_literal` never fires under `tyc check`

The secret-shaped-name lint is emitted from `tyc/src/commands/build.rs`, so it
only appears during `tyc build`. `docs/cli.md` and the skill both recommend
`tyc check src/` as the CI primary gate — a pipeline that follows that advice
will never see this warning, and a resolved API key inlined into the build
artifact ships unflagged.

Worth either moving the scan into the check path or adding a note to the CI
recommendation. Documented in the corpus meanwhile.

Reproduction: `examples/errors/10-footguns-and-lints/contains_secret_literal.ty`
(carries a `# REQUIRES: build` directive for exactly this reason).

### C5 — three raw-source validators mask every other diagnostic in the file

`tyc::invalid_question_op`, `tyc::lazy_usage` and `tyc::extend_builtin` are
produced by validators that run on raw text before preprocessing, and
`check_source_file_with_imports` returns immediately if any of them errors
(`tyc-db/src/lib.rs`). One misplaced `?` therefore hides every type error in
the file:

```python
def bad() -> str:
    let n: int = f()?        # tyc::invalid_question_op — the only code reported
def unrelated() -> int:
    let s: str = "hello"
    return s                 # tyc::type_mismatch — never surfaces
```

Measured on a realistic file: 1 diagnostic reported where 10 exist across 7
codes. This is structurally necessary (those three forms are *text rewrites*,
so a malformed one leaves nothing to parse) and not obviously worth changing —
but it is surprising enough to be worth documenting, since it turns one fix
into several fix-recheck cycles.

Documented in `examples/errors/11-multi-error-programs/error_masking.ty`.

### C6 — `tyc install skill` silently dropped a file *(fixed)*

`references/21-rescue-boundaries.ty` existed in `tyc/crates/tyc/skill/` and was
indexed by the skill's own `references/README.md`, but was missing from the
`SKILL_FILES` manifest — so every project that ran `tyc install skill` got 20
reference programs and an index promising 21.

Fixed, plus a `manifest_covers_every_file_in_the_skill_source_tree` test so the
hand-maintained manifest can't drift again, and the "20 example programs"
summary line is now derived from the manifest.

### C7 — two warn-level diagnostics rendered with the error glyph *(fixed)*

`tyc::method_in_class_body` and `tyc::typing_alias_deprecated` were counted and
grouped as warnings but drew miette's `×` rather than `⚠`, because their
declarations omitted `severity(Warning)`. Every other warn-level code in the
catalog declares it. Cosmetic, but a warning that looks like an error costs
someone a debugging detour. Fixed.

### C8 — `tyc explain --list` advertised two codes that don't exist *(fixed)*

`freeze` and `pub` are language-reference topics with pages under
`docs/diagnostics/`; they were printed as `tyc::freeze` / `tyc::pub` alongside
the 87 real codes, so anyone reading the list would expect them in build
output. They are now labelled `(topic, not a diagnostic code)`.

### Verified as accurate

Worth recording what held up, since it is most of the surface. Every one of
these was probed against the binary: the eight rules; `let`/`mut`/`freeze let`
semantics; the `class` / `model` / `plain class` / `class!` / `enum` / `frozen`
matrix; sealed unions and exhaustiveness (including `case Nil()` vs the
never-matching `case Nil(_)`); `Result` / `?` / `with`-chains / `try_result` /
`rescue`; `gather:` (including the documented graceful degradation to
sequential awaits when one binding depends on another — verified in the emitted
Python); `go … -> task`; `newtype` asymmetry and same-newtype arithmetic;
`as!` composition; `extend str:`; `pub` stacking with every modifier *except*
`pub lazy let` (correctly documented as not parsing); every "designed but not
supported" entry in `SKILL.md` §7; the whole `typhon.toml` surface
(`[optimise] level`, `3.15` targets, `parallel-backend`, unknown-key
rejection); and the CLI flag surface (`-O`, `--with-ty`, `--temp`,
`tyc install skill`).

## 5. Test-coverage gaps closed

`CLAUDE.md` calls the example corpus "the regression net". It was partly
enforced: `pipeline.rs::corpus_examples_all_check_clean` sweeps every `.ty`
under `examples/` as a *standalone file* and asserts the exit status. Three
things it did not cover, now added in `tests/example_corpus.rs`:

1. **The 16 multi-file projects** (`examples/apps/*`, `47-mini-app`) were never
   checked as projects — only their files individually, which does not exercise
   cross-module resolution, `pub *` aggregation, or the shape registry.
2. **Warnings.** The sweep only checked exit status, so a new warning firing
   across the whole corpus would not have been noticed.
3. **The `.py` companions.** `examples/README.md` promises they show "exactly
   what each Typhon construct lowers to"; nothing verified that.

Both new harnesses run under `cargo test --workspace`, so CI enforces them with
no workflow change. Combined cost: ~5s.

## 6. `examples/errors/` — the new corpus

70 deliberately-broken programs across twelve themed directories, covering
**56 of the 87** emittable codes. Each file is a small realistic program with a
header comment that names its diagnostics, explains the rule, and shows the
fix — the prose is the deliverable; the broken code is the exhibit.

`11-multi-error-programs/` is the "one to many errors" end: `python_habits.ty`
is ordinary Python and every habit Typhon asks you to change; `order_service.ty`
carries ten diagnostics across seven codes; `error_masking.ty` documents C5.

`12-known-gaps/` inverts the format — programs that compile clean and fail at
runtime, one per finding C1–C3. They are asserted to produce *no* diagnostics,
so closing a gap fails the test as a prompt to reclassify the file rather than
letting the record rot.

See `examples/errors/README.md`.

## 7. Recommended follow-ups, in priority order

1. **C1 — the silent missing `await`.** A real soundness hole with a runtime
   crash behind it. Narrow rule proposed above; permitted under the
   additivity constraint since the rejected programs already crash.
2. **C4 — move the secret-literal scan into `tyc check`,** or amend the CI
   recommendation. Security-relevant and cheap.
3. **C2 — extend `implicit_any` to signatures.** Zero measured corpus impact;
   needs an explicit narrowing decision plus a changelog note.
4. **C3 — decide `missing_initialiser`'s fate:** wire it up as a dead-binding
   lint, or retire the code and its `tyc explain` entry.
5. **The 77 non-`fmt`-clean example files.** Either reformat and accept losing
   the hand alignment, or document that the corpus is intentionally
   hand-formatted so nobody "fixes" it in a drive-by.
