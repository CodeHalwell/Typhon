# W2-08 validation

Integer powers with negative literal exponents return float; unknown-sign integer exponents return int | float (or the integer newtype | float). Proven nonnegative literal powers, including nested powers, retain the integer type. Augmented assignment checks the operation result against the target's declared type, including bool arithmetic, numeric widening, powers, overloaded operators and tuple concatenation. Nullable operands report nullable_use before stripping their payload types. Mutable list extension keeps its element check.

The regression failed before the fix. Rust 1.94.1 fmt, all 678 checker tests, clippy and CLI build pass. Final corpus: 1,481 units, 1,219 accepted, 262 rejected. The valid nested-power numeric-edge unit remains accepted.

Three additional units expose unsound integer power contracts:
- `stress/round-2026-09-01/types/h101_pow.ty`: 2 ** -1 is float; bit_length raises AttributeError.
- `stress/round-2026-06-21/repros/118-cast-partial.ty`: its declared `power(2, -1) -> int` produces float; bit_length raises AttributeError.
- `stress/round-2026-06-21/repros/78-deep-recursion-bignum.ty`: its declared `power_tower(-2, 2) -> int` produces float; bit_length raises AttributeError.

The latter two main functions use positive inputs; validation invokes the functions with other inputs allowed by their existing signatures. CPython 3.13 reproduction is in power_runtime_test.py. Other corpus outcomes match W2-07. Baseline changes are handed to W5.
