Typhon ships as a single Rust binary called `tyc`. The fastest way to get it is a pre-built binary from the latest GitHub Release; you can also build from source with one `cargo` command. Optional integrations (`tyc ty`, `tyc stubtest`) shell out to Python tools you can install on demand.

## Install a pre-built binary (recommended)

Pre-built, checksum-verified binaries ship on every [GitHub Release](https://github.com/CodeHalwell/Typhon/releases) for Linux (x86_64/aarch64), macOS (Apple Silicon/Intel), and Windows (x86_64).

<Tabs>
<TabItem label="macOS / Linux">

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/codehalwell/typhon/main/install.sh | sh
```

The installer detects your platform, downloads the matching archive, verifies its SHA-256 against the release manifest over TLS, checks its [build provenance](#verifying-a-download) when the GitHub CLI is available, and installs `tyc` to a per-user directory (no `sudo`). Pin a version with `--version=v1.0.0-beta.7` (or `TYPHON_VERSION=…`).

</TabItem>
<TabItem label="Windows (PowerShell)">

```powershell
iwr -useb https://raw.githubusercontent.com/codehalwell/typhon/main/install.ps1 | iex
```

</TabItem>
<TabItem label="Manual download">

Download the archive for your platform from the newest entry on the [releases page](https://github.com/CodeHalwell/Typhon/releases) (GitHub's "latest release" link skips pre-releases, so use the full list while Typhon is pre-1.0), verify it against `SHA256SUMS`, extract it, and put `tyc` on your `PATH`.

Follow the [manual installation steps](https://typhon.sh/install#manual) for macOS, Linux or Windows, including checksum comparison, extraction and PATH setup.

</TabItem>
</Tabs>

If your platform isn't listed (FreeBSD, Linux MUSL, Windows ARM64), build from source below.

## Verifying a download

Every release archive can be checked two ways. Both installers always do the first, and do the second when they can.

**Checksum.** Each release carries a `SHA256SUMS` file. Download it next to the archive and compare:

```bash
# macOS: shasum -a 256 -c SHA256SUMS --ignore-missing
sha256sum -c SHA256SUMS --ignore-missing
```

This catches a corrupted or truncated download. It does not protect against a tampered release, because `SHA256SUMS` comes from the same place as the archive.

**Build provenance.** Releases after v1.0.0-beta.7 also carry a signed build-provenance attestation for every archive, produced by the release workflow. With the [GitHub CLI](https://cli.github.com/) installed and logged in:

```bash
gh attestation verify tyc-<version>-<target>.tar.gz --repo CodeHalwell/Typhon
```

Success means the archive was built by a GitHub Actions run in `CodeHalwell/Typhon`.

The installers run this check themselves when `gh` is on your `PATH`. An archive whose attestation does not verify aborts the install. When there is nothing to verify against (v1.0.0-beta.7 or older, or `gh` missing or not logged in), the installer prints a note and continues on the checksum alone.

<Aside type="tip">
Set `TYPHON_REQUIRE_ATTESTATION=1` to make anything short of a successful provenance check fatal:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/codehalwell/typhon/main/install.sh | TYPHON_REQUIRE_ATTESTATION=1 sh
```
</Aside>

## Verify the installation

```bash
tyc --version
```

The current prerelease prints `tyc 1.0.0-beta.7`. If the command is not found, open a new terminal and check that the install directory is on your `PATH`. See [troubleshooting](#troubleshooting) for compiler and editor setup issues.

## Prerequisites (build from source)

- **A Rust toolchain** — the repo pins Rust **1.94** (`tyc/rust-toolchain.toml`); the vendored crates require **1.93+**, so an older `cargo` will refuse to build. Install via [rustup](https://rustup.rs/) if you don't already have it.
- **A Python interpreter** — CPython 3.13, 3.14 or 3.15, including their free-threaded `t` variants. Typhon emits code targeting 3.13 by default; [configure the target](/Typhon/configuration/python/) in `typhon.toml` for newer syntax and builtins.
- **(Optional) `uv`** — Astral's package manager. Used by `tyc add` / `tyc remove` / `tyc sync` for dependency installation. Install with `pipx install uv` or via [the uv install script](https://docs.astral.sh/uv/getting-started/installation/).
- **(Optional) `ty`** — Astral's Python type checker. Used by `tyc ty` for a second-opinion typing pass against the emitted Python. Install with `pip install ty` or `uv tool install ty`.

## Build from source

<Steps>

1. **Clone the repository.**

   ```bash
   git clone https://github.com/CodeHalwell/Typhon.git
   cd Typhon
   ```

2. **Build the compiler in release mode.**

   ```bash
   cd tyc
   cargo build --release
   ```

   This produces `tyc/target/release/tyc`. The first build will take a few minutes (the vendored Ruff fork is large); subsequent builds are incremental.

3. **Put it on your PATH.** Either copy the binary to a directory already on `PATH`, or alias it.

   <Tabs>
     <TabItem label="Symlink" icon="seti:bash">
       ```bash
       sudo ln -s "$PWD/target/release/tyc" /usr/local/bin/tyc
       ```
     </TabItem>
     <TabItem label="Bash/zsh alias" icon="seti:bash">
       ```bash
       echo "alias tyc='$PWD/target/release/tyc'" >> ~/.bashrc
       # or ~/.zshrc
       source ~/.bashrc
       ```
     </TabItem>
     <TabItem label="Fish alias" icon="seti:bash">
       ```fish
       alias --save tyc "$PWD/target/release/tyc"
       ```
     </TabItem>
   </Tabs>

4. **Verify the install.**

   ```bash
   tyc --version
   tyc --help
   ```

   You should see the version banner and the list of subcommands.

</Steps>

## Updating

For a prebuilt installation, rerun the installer or download the new archive and verify its checksum. For a source checkout, pull the latest commits and rebuild:

```bash
cd /path/to/Typhon
git pull
cd tyc && cargo build --release
```

If you symlinked, you don't need to redo it; the symlink points at the freshly-rebuilt binary.

For a second-opinion pass over the emitted Python:

  </TabItem>

  </TabItem>

Then run [`tyc ty`](/Typhon/cli/ty/) in any Typhon project.

### `mypy` (for `tyc stubtest`)

The runtime-introspection probe for `.dty` / `.pyi` stub drift:

```bash
pip install mypy
# or
uv tool install mypy
```

Then run [`tyc stubtest`](/Typhon/cli/stubtest/) in projects that ship stubs.

### `uv` (for `tyc add` / `remove` / `sync`)

The package-manager surface shells out to `uv` for installs. Without `uv`, `tyc add` / `remove` still edit `typhon.toml`; they just won't install. Recommended:

```bash
pipx install uv
# or
curl -LsSf https://astral.sh/uv/install.sh | sh
```

## VS Code extension (reference)

The repository ships a reference VS Code extension under `editors/vscode/`. It wires up `tyc lsp` over stdio. To install:

```bash
cd editors/vscode
npm install
npm run package          # produces typhon-X.Y.Z.vsix
code --install-extension typhon-*.vsix
```

Restart VS Code; opening a `.ty` file should give you syntax highlighting and diagnostics on save. See [editors/vscode/README.md](https://github.com/CodeHalwell/Typhon/blob/main/editors/vscode/README.md) for details.

Other LSP-aware editors (Neovim, Helix, Zed, etc.) can wire `tyc lsp` directly. See [Editor Setup](/Typhon/getting-started/editor-setup/) for examples.

## Troubleshooting

### "command not found: cargo"

Install Rust via [rustup](https://rustup.rs/). On the first run it sets up `cargo`, `rustc`, and the toolchain in `~/.cargo/bin`. Open a new shell or `source $HOME/.cargo/env` to pick it up.

### Build fails with linker errors

You need a working C linker. On Linux: `sudo apt install build-essential` (Debian / Ubuntu) or `sudo dnf install gcc` (Fedora). On macOS: `xcode-select --install`. On Windows: install Visual Studio Build Tools.

### "tyc check" complains about missing typhon.toml

You're running outside a Typhon project. Either `cd` into one or scaffold one first with [`tyc init`](/Typhon/cli/init/).

### LSP doesn't start in VS Code

Open the Output panel (`View → Output`) and select "Typhon" from the dropdown. The extension logs the `tyc lsp` invocation; if `tyc` is not on the PATH the editor process sees, the LSP won't start. Set the binary path in extension settings, or fix your `PATH`.

### Cargo build is slow

The first `cargo build --release` rebuilds the entire vendored Ruff fork plus every Typhon crate. Subsequent builds are incremental. If you're hacking on the compiler, `cargo build` (debug mode) is faster.
