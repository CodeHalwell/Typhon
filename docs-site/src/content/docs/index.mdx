## The 30-second pitch

> Every `.ty` file emits valid, idiomatic `.py`. Not all `.py` is valid Typhon.

Typhon is what Python could look like if you started over with three decades of language-design hindsight, while still keeping every Python library you love. It is a *compile-to-Python* language in the same sense that TypeScript is a *compile-to-JavaScript* language: you write the stricter, safer, more ergonomic dialect, and the compiler hands you idiomatic CPython that runs everywhere Python runs — no Typhon runtime, no PyPI dependency, no special interpreter.

<Tabs syncKey="pitch">
  <TabItem label="Typhon">

```python
type LoadError = NotFound | Timeout

class NotFound:
    path: str
class Timeout:
    after_ms: int

def load(path: str) -> Result[str, LoadError]:
    try:
        with open(path) as f:
            return Ok(f.read())
    except FileNotFoundError:
        return Err(NotFound(path=path))

def main() -> None:
    match load("config.toml"):
        case Ok(body):
            print(body)
        case Err(NotFound(path)):
            print(f"missing: {path}")
        case Err(Timeout(after_ms)):
            print(f"timed out after {after_ms}ms")
```

  </TabItem>
  <TabItem label="Emitted Python">

```python
from dataclasses import dataclass
from typhon_runtime import Ok, Err

@dataclass(slots=True)
class NotFound:
    path: str

@dataclass(slots=True)
class Timeout:
    after_ms: int

LoadError = NotFound | Timeout

def load(path: str) -> Ok[str] | Err[LoadError]:
    try:
        with open(path) as f:
            return Ok(f.read())
    except FileNotFoundError:
        return Err(NotFound(path=path))

def main() -> None:
    match load("config.toml"):
        case Ok(body):
            print(body)
        case Err(NotFound(path)):
            print(f"missing: {path}")
        case Err(Timeout(after_ms)):
            print(f"timed out after {after_ms}ms")
```

  </TabItem>
</Tabs>

The match on `LoadError` is statically exhaustive — add a third variant to the union and every match site goes red until you handle it. That is, in one screenshot, the kind of safety Typhon brings to Python.

## What you get

<CardGrid>
  <Card title="Non-nullable by default" icon="approve-check">
    Plain `T` cannot hold `None`. Use `T?` when you mean optional. Flow narrowing on `is None`, `is not None`, `isinstance`, `guard`, and early returns.
  </Card>
  <Card title="No implicit Any" icon="warning">
    Untyped values are a hard error outside `unsafe:` blocks. The strictness is stronger than TypeScript's `noImplicitAny`.
  </Card>
  <Card title="Errors as values" icon="puzzle">
    `Result[T, E]`, `Ok`, `Err`, and the `?` operator make failure visible in signatures — without giving up Python's exception bridge.
  </Card>
  <Card title="Sealed unions + exhaustive match" icon="setting">
    `type Shape = Circle | Rectangle | Triangle`. Add a variant; every `match` lights up red. Refactor with confidence.
  </Card>
  <Card title="Explicit async, smarter concurrency" icon="rocket">
    `gather:` lowers to `asyncio.TaskGroup` (the safe default). `go f(x)` spawns fire-and-forget through a strong-ref registry. No GC'd tasks.
  </Card>
  <Card title="Build-time configuration" icon="seti:config">
    `comptime let PORT: int = int(env("PORT", "8080"))` inlines at build time. Missing required env vars fail the build, not production.
  </Card>
  <Card title="Clean output, no runtime tax" icon="document">
    Emits idiomatic Python you can read, debug, and ship. The handful of helpers (`Result`, `lazy`, task registry) is generated locally as `typhon_runtime/`. No PyPI install.
  </Card>
  <Card title="One binary, full pipeline" icon="terminal">
    `tyc` is the compiler, formatter, language server, REPL, in-process VM, migrator, debugger launcher, and package-manager surface — sub-100ms incremental feedback via Salsa.
  </Card>
</CardGrid>

scheduler) and the release closes every issue from that campaign, plus three additive features (`Ok` / `Err` `Result`-combinator methods, `impl` on a sealed-union alias distributing to every variant, `tyc::stdlib_module_shadow` warning). **[v0.6.1](https://github.com/CodeHalwell/Typhon/releases/tag/v0.6.1)** is a polish release on top of v0.6.0: `let name: lowercase_type = …` highlights as a type annotation, and `.py.map` sidecars now live under `<out>/.sourcemaps/` mirroring the emitted Python tree. **[v0.7.0](https://github.com/CodeHalwell/Typhon/releases/tag/v0.7.0)** is the Round-3 apps-feedback carry-over: `pub *` wildcard re-export aggregation in `__init__.ty`, declare-only `let NAME: T` with arm-assignment, `with cm() as r:` inference from `__enter__` / `@contextmanager`, `await Callable[..., Awaitable[T]]` unwrapping, same-newtype-preserving arithmetic, cross-module generic method dispatch, ternary narrowing, `tyc::field_default_ordering`, and five new apps under `examples/apps/`. **[v0.7.1](https://github.com/CodeHalwell/Typhon/releases/tag/v0.7.1)** is a strict LSP bugfix point release. **[v0.8.0](https://github.com/CodeHalwell/Typhon/releases/tag/v0.8.0)** is the stress-test sweep release that closes **41 findings** spanning the type checker, VM, parser, lowering passes, diagnostics, and CLI. **[v0.8.1](https://github.com/CodeHalwell/Typhon/releases/tag/v0.8.1)** is a point release that adds a `partial` `InterfaceShape` marker so venv-introspected third-party classes don't false-positive `attribute_not_found`. **Current release: [v0.9.0](https://github.com/CodeHalwell/Typhon/releases/tag/v0.9.0)** — the stress-test cleanup release closing **32 findings** from a v0.8.1 stress sweep. The VM is now usable as the daily-driver runner the docs always advertised: `Result` combinators (`.map` / `.map_err` / `.and_then` / `.or_else`), `open()` write/append/binary modes, class patterns on built-in types (`case str() as s:`), `frozenset` as a dict key, deep `freeze let` (list → tuple, dict → mappingproxy, recursive), comptime inlining, `lazy import`, `class!` exception fields surviving `except X as e:`, dataclass mutable-default factories invoked per instance, `collections.deque` / `heapq` / `contextlib` / `pydantic` shims, multi-file projects with relative imports, and `@property` / `super()` / `@contextmanager` all work under `tyc run`. The type checker plugs silent-correctness gaps: read-view covariance (`list[Dog] → Sequence[Animal]`), variant-to-parametric-union flow (`Cons[T] → LinkedList[T]`), `while True:` reachability, post-while-loop narrowing, `assert x is not None` narrowing, `*args` / `**kwargs` annotation policy, `extend list:` dispatch on `list[T]` receivers, exhaustive match on `T?` with built-in class patterns, `with`-chain explicit `else err: return Err(err)` error-type validation, `func[T](args)` clear check-time error, and `comptime let T: type = int` lowering to PEP 695 type aliases. `pub *` collisions now surface in `tyc check` (not just `tyc build`); sealed-union impl distribution diagnostics dedupe so a 10-variant union no longer reports 10 identical errors. Additive on the accepted surface; the BigInt switch in the VM means programs that relied on silent i64 wrap-around compute different (correct) results. The minimum-viable language — non-null types, sealed unions, `Result`, dataclass emit — is shippable today.

Typhon targets CPython 3.13+ (and the free-threaded 3.13t/3.14t builds when you opt in). It is not a new runtime, not a Mojo-style separate language, and not a replacement for the Python you already write. It is the language you reach for when you want Python's libraries with Rust-flavoured static safety and ergonomics.
