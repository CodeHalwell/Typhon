## `tyc::nullable_use`

Passing or using a `T?` value where a `T` is required, without narrowing first:

```python
def greet(name: str) -> None: ...
def find_user(id: int) -> str?: ...

let found: str? = find_user(1)
greet(found)    # ❌
```

**Fix:** narrow before use. Seven forms (the last two added in v0.9.0):

```python
# 1. is None / is not None
if found is not None:
    greet(found)

# 2. Early return
if found is None:
    return
greet(found)

# 3. isinstance
if isinstance(found, str):
    greet(found)

# 4. guard
guard f = found else: return
greet(f)

# 5. or-fallback
greet(found or "anonymous")

# 6. assert (v0.9.0) — standard Python static-checker idiom
assert found is not None
greet(found)

# 7. Post-while-loop (v0.9.0) — body sets it, loop must have exited
mut cfg: Config? = None
while cfg is None:
    cfg = load_next()
greet(cfg)                   # narrowed to non-None
```

See [Flow Narrowing](/Typhon/types/narrowing/) for every form the checker recognises.

**Note on `assert`:** disabling assertions with `python -O` removes the runtime guard, so safety-critical narrowing should still go through `guard` or `if x is None: return`. `assert` is best as a "this can't happen" checkpoint inside functions that already validated their inputs.

## What does *not* narrow

- **Fields and attribute paths** — `if u.email is not None: u.email.upper()` does not narrow `u.email`. Copy to a local first.
- **Indexed access** — `if xs[0] is not None:` does not narrow `xs[0]`.
- **Cross-mutation** — explicit `u.refresh()` in between invalidates the narrowing on `u`'s fields.

See [Flow Narrowing](/Typhon/types/narrowing/) for the rules and limits.
