# Typhon v0.7.1 Stress-Test Report

Findings from a multi-file stress sweep (~80 `.ty` files) spanning collections,
generics, sealed unions, Result chains, async, comptime, classes/models/
inheritance, lazy imports, ML stubs, an agent framework, an API microservice,
the VM (`tyc run`), formatter, REPL, `tyc migrate`, and `tyc trace`.

**Overall:** the compiler & static checker are strong — most v0.3.0+ language
features fire their advertised diagnostics. The **VM (`tyc run`) is
significantly weaker than its docs imply**, and there are **two serious holes
in the static checker** (attribute access on classes, interface signature
conformance). Detailed findings below, grouped by severity.

---

## 🔴 Critical — type-checker holes that defeat core guarantees

### 1. `tyc::attribute_not_found` is documented but never fires

Tested on user classes, builtins, `list`/`dict`/`set`. **All silently accepted.**

```ty
class Foo:
    x: int

def main() -> None:
    let f: Foo = Foo(x=1)
    print(f.y)                       # passes check — should be attribute_not_found
    print(f.totally_made_up_field)   # passes check
    print("hi".bogus_method())       # passes check
    let xs: list[int] = [1,2,3]
    print(xs.fake_method())          # passes check
```

Even kwarg-typo detection works (`Cfg(prt=80)` → "did you mean `port`?"), but
bare attribute access has no checker. This is the single biggest "static
typing" guarantee a user expects, and it's missing.

### 2. Interface signature mismatches are NOT enforced

```ty
interface Repo:
    def save(self, item: str) -> bool

class BadRepo:
    pass

impl BadRepo:
    def save(self, item: int) -> bool:   # wrong arg type
        return True

def use(r: Repo) -> None: pass
use(BadRepo())                            # passes check
```

Conformance only checks method *presence*, not parameter type compatibility —
defeating most of the interface guarantee. (`interface_not_conforming` does
fire for *missing* methods.)

### 3. `let xs = []` (no annotation) passes

```ty
let xs = []
xs.append("string")
xs.append(42)
let total: int = sum(xs)   # passes check
```

The pitfalls page warns about `let xs: list = []` but `let xs = []` slips
through. Empty-literal inference is effectively `Any`, masking real bugs.

### 4. Bare `List[int]`, `Optional[int]`, `Dict[str, int]`, `Union[int, str]` are silently accepted

Importing them is rejected (`typing_alias_deprecated`), but using them as
forward-reference names is fine. Inconsistent: either reject the bare names
too or accept the imports.

### 5. `?` error-type mismatch goes uncaught inside `with`-chains

Plain `let s: str = fetch(id)?` correctly fires `result_error_mismatch`, but:

```ty
def combine(s: str, id: int) -> Result[str, str]:
    with n = parse(s)?, name = fetch(id)?:   # fetch returns Result[str, int] - mismatch
        return Ok(name)
    else err:
        return Err(str(err))
```

is silent.

## 🟠 Major — language features that don't behave per docs

### 6. HKT scaffold `class Functor[F[_]]:` doesn't parse

Docs claim v0.5.0+ support. Skill table even lists it as working. Parser fails
at `[_]`.

### 7. `impl SealedUnionAlias:` doesn't work

Docs (v0.6.0) claim methods distribute to every variant:

```ty
type Tree[T] = Leaf[T] | Branch[T]

impl[T] Tree[T]:    # fails with tyc::impl_unknown_class
    def depth(self) -> int: ...
```

### 8. `class X[T] frozen:` (generic + frozen) doesn't parse

Either `[T]` or `frozen` alone works, but the combination fails with
`Expected ":", found name`.

### 9. Interface bodies don't support `async def` without explicit `: ...` body

The preprocessor auto-appends `: ...` only to sync `def`:

```ty
interface Tool:
    def name(self) -> str                      # OK (auto-completed)
    async def execute(self, args: dict) -> X   # parse error
```

### 10. `tyc::contains_secret_literal` warning never fires

Tested with `API_TOKEN`, `DB_PASSWORD`, `OPENAI_API_KEY`, `MY_SECRET`,
`DB_PWD` — both env-driven and explicit string values. No warning.

### 11. `tyc::pattern_shadows_outer` never fires

```ty
let value: int = 42
match r:
    case Ok(value): print(value)   # should warn — silent
```

### 12. `tyc::field_default_ordering` false-positives on `ClassVar`

```ty
from typing import ClassVar
class Config:
    DEFAULT_PORT: ClassVar[int] = 8080   # excluded from __init__
    host: str                            # error: non-default after default
```

`ClassVar` doesn't participate in `__init__` generation; ordering rule should
exclude it.

### 13. String-literal union types accept any string

```ty
type Color = "red" | "green" | "blue"
paint("orange")    # passes — no Literal[...] enforcement
```

### 14. `newtype Bogus = "any string literal"` is silently accepted

Should reject non-type RHS.

### 15. Match exhaustiveness can't reason about guards covering all values

```ty
def classify(t: Token) -> str:
    match t:
        case IntTok(v) if v > 0: return "pos"
        case IntTok(v) if v < 0: return "neg"
        case IntTok(0):          return "zero"
        case ...
```

Fires `tyc::missing_return` even though IntTok is exhaustively covered.

### 16. Function parameter rebinding doesn't require `mut`

```ty
def f(x: int) -> int:
    x = x + 1   # passes — inconsistent with `let`/`mut` rule
    return x
```

### 17. Outer-annotation tuple unpack is rejected

```ty
let (a, b): tuple[int, str] = pair()    # parse error
let (a: int, b: str) = pair()           # OK (per-element form)
```

Spec table is ambiguous about which forms are supported.

## 🟠 Major — VM (`tyc run`) divergences from CPython

### 18. VM does NOT preserve dict insertion order

```ty
let a: dict[str, int] = {"a": 1, "b": 2, "c": 3, "d": 4, "e": 5}
print(a)   # VM:    {'a': 1, 'd': 4, 'e': 5, 'c': 3, 'b': 2}
           # Python: {'a': 1, 'b': 2, 'c': 3, 'd': 4, 'e': 5}
```

Python guarantees insertion order since 3.7. **The same `.ty` file produces
different output under `tyc run` and `tyc build && python build/main.py` for
any dict-printing program.**

### 19. VM uses i64 ints, spec claims arbitrary precision

```
VM:     2 ** 100  →  OverflowError: int overflow
Python: 2 ** 100  →  1267650600228229401496703205376
```

`fib(99)` also overflows. Spec says: "`int` Arbitrary precision (matches
CPython). VM today uses `i64`." This is a documented limitation that
nonetheless contradicts the language spec.

### 20. VM f-string formatter ignores `0` zero-pad and `#` alternate-form flags

```
f"{42:04d}"   VM: "  42"    Python: "0042"
f"{42:06}"    VM: "    42"  Python: "000042"
f"{42:#x}"    VM: "2a"      Python: "0x2a"
f"{3.14:08.3f}"  VM: "   3.142"  Python: "0003.142"
```

### 21. VM doesn't apply `extend BUILTIN:` rewrites

Type check passes, runtime fails:

```ty
extend str:
    def slug(self) -> str: return self.lower().replace(" ", "-")

"Hello".slug()    # check OK; tyc run: AttributeError: str has no method 'slug'
```

`tyc run --compile` works correctly.

### 22. VM subclass constructors don't inherit fields

```ty
class Animal: name: str; age: int
class Dog(Animal): breed: str

Dog(name="Rex", age=5, breed="Husky")
# check OK; tyc run: TypeError: Dog() got unexpected keyword argument(s): name, age
```

Same for multiple inheritance (`class C(A, B):`). Compile mode works.

### 23. VM doesn't shim `freeze let`

```
NameError: name '__typhon_freeze__' is not defined
```

### 24. VM doesn't shim `NewType`

```
NameError: name 'NewType' is not defined
```

Any `newtype Foo = int` crashes in VM mode.

### 25. VM crashes on `from typing import Callable`

```
ImportError: tyc-vm cannot import 'typing'
```

Even when `Callable` is used only as a type annotation. Lowering should strip
`typing` imports for VM mode.

### 26. VM crashes on `lazy let` inside class

Lowers to `@cached_property` from `functools`; VM has no `functools`.

### 27. VM stdlib is extremely sparse

Probed each module with `import X`:

| Works | Fails |
|---|---|
| `os`, `sys`, `math`, `json` | `re`, `typing`, `collections`, `dataclasses`, `functools`, `itertools`, `pathlib` |

Combined with #25, most non-trivial Typhon programs can't run in the VM.

### 28. VM doesn't support generators (`yield`)

`NotImplementedError: async / generators`. Static checker is silent.

### 29. VM doesn't support async at all

Same `NotImplementedError`. Static checker is silent.

### 30. VM doesn't support complex match patterns

`case {"type": "circle"}` and `case [x, *rest]` both crash:
`NotImplementedError: complex match patterns`.

### 31. VM recursion limit is ~250

Python defaults to 1000. Stack-busts much earlier than expected with no docs.

## 🟡 Diagnostics quality

### 32. Diagnostic source listing shows post-preprocessing/desugared text

Recurring across many tests:

- `comptime let X = …` → diagnostic shows `let X = …` (comptime keyword eaten)
- User has no `import` line but diagnostic shows
  `from typhon_runtime import Err as __typhon_Err__`
- `impl Foo:` → diagnostic shows `class __typhon_impl_Foo(object):`
- `let s: str = fetch(id)?` → `result_error_mismatch` points at synthetic
  `if isinstance(__typhon_q_0__, __typhon_Err__):` line

Spans must be re-mapped back to original source for user-facing errors.

### 33. Migrator (`tyc migrate`) produces uncompilable Typhon

```python
# input
class Box(Generic[T]):
    def __init__(self, value: T) -> None:
        self.value = value
```

becomes

```ty
class! Box[T]:
    def __init__(self, value: T) -> None:
        self.value = value
```

which fails `tyc check` with `manual_init`. Also `class!` is meant for
framework bases only; using it for any class with `__init__` is a
misapplication. Migrator needs a trivial-init recognizer.

### 34. Multi-line `|>` without parens errors as "Unexpected indentation"

Should be a dedicated "wrap pipe chain in parens" diagnostic.

### 35. `freeze let` inside a function errors as "Simple statements must be separated by newlines or semicolons"

Should be a dedicated "freeze let is module-level only" diagnostic.

### 36. `tyc::arg_count` says "expected 2, got 2" for kw-only mismatches

```ty
def f(*, a: int, b: int) -> int: return a + b
f(1, 2)   # error: "expected 2, got 2"
```

Message is self-contradictory; should be a dedicated "positional arg passed
to keyword-only parameter" diagnostic.

### 37. Variance error hint is misleading

`list[Dog]` → `list[Animal]` hints "widen to `list[Animal] | list[Dog]`" —
almost never what you want. Should suggest `Sequence[Animal]` (covariant) or
rebinding the source as `list[Animal]`.

### 38. Dict-literal-to-model mismatch error doesn't name missing fields

```ty
model UserCreate: name: str; age: int; email: str
let u: UserCreate = {"name": "Bob"}
# "expected UserCreate, found dict[str, str]"
```

Needs "missing fields: age, email".

### 39. `tyc check lib.dty` reports "checked 0 file(s)"

Single-file `.dty` checking is a silent no-op with no user feedback.

### 40. `tyc run --compile` on a single `.ty` file gives confusing error

```
× source directory '/tmp/foo.ty/src' does not exist
```

CLI should either support single-file compile or give a meaningful message.

### 41. `unused_import` is severity `error` by default

Almost every test required an unused-import cleanup pass. Most linters treat
this as a warning. Recommend default `"warn"` or a formatter auto-fix.

## 🟢 Working well (confirmed strengths)

- Result/`?`/`with`-chain semantics, combinators, sealed unions, exhaustive match
- Declare-only `let NAME: T` with definite-assignment (`use_of_uninitialised`,
  handles `try`/`if`/`match` correctly)
- `freeze let` deep-immutable bindings (in compile mode)
- Newtype arithmetic preservation (`+ - * // % **`) and asymmetric base↔newtype
  flow; cross-newtype rejection
- `unsafe:` blocks with `unsafe_value_leak` detection
- `field_default_ordering` for ordinary fields, `manual_init`,
  `method_in_class_body`, `class_attr_shadows_slot`
- Purity analysis (`@pure`) catching IO, mutation, `global`, unhashable args
- `div_by_zero_literal` including `-0.0` and `-0`
- Interface presence-conformance, `interface_isinstance` rejection
- `gather:`, `go`, `@gatherable`, `blocking_in_async`, `async_without_await`
- `resource_not_managed` for `open`, `socket`, `sqlite3.connect`, `tempfile.*`
- Variance for `list` (invariant) and tuple (covariant per slot)
- `stdlib_module_shadow` (works inside a project)
- `cyclic_type_alias`
- `tyc trace` round-trips Python `.py` lines back to `.ty`
- `tyc fmt`, REPL basics, `tyc explain --list`, `tyc explain <code>`
- `unknown_kwarg` with "did you mean" suggestions

## Recommended priority order

**Tier 0 — correctness, ship-stoppers**
- #1 `attribute_not_found` not firing
- #18 VM dict insertion-order divergence
- #19 VM int width vs spec

**Tier 1 — high-impact bugs**
- #2 interface signatures not checked
- #5 `?` mismatch in `with`-chains
- #12 `ClassVar` false-positive in field-ordering check
- #21 / #22 VM extend-builtin and inheritance gaps
- #28 / #29 VM async/generators — at least static warnings
- #32 spans pointing at desugared text

**Tier 2 — doc/behaviour mismatches**
- #6 / #7 HKT and `impl SealedUnionAlias`
- #8 generic + `frozen` combination
- #10 secret-literal warning
- #11 pattern-shadows-outer warning
- #14 newtype string-literal base
- #23 / #24 `freeze` and `NewType` in VM
- #25 / #27 VM stdlib coverage

**Tier 3 — quality of life**
- #4 bare `typing` names
- #16 parameter mutability rule
- #33 migrator producing uncompilable output
- #34–#41 diagnostic phrasing & CLI ergonomics

A handful of these (#1, #2, #18) are surprising for a 0.7-versioned tool —
they're the kind of defects that erode trust quickly if a user hits them in
production. The rest are polish or VM-mode caveats; the core static surface
above the VM is impressive.
